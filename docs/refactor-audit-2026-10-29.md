## 保存结构

```text
模块内容契约
  ├─ Admin 编辑适配器 → 不可变资源变更 → 单一保存队列
  └─ 共用展示适配器 → 本地预览 / 公开站构建

PATCH：请求编号 + 改变的资源 + 各资源预期版本
  → 校验资源与页面结构
  → 事务：工作区版本 + 资源当前值 + 资源历史 + 审计
  → 回执：自客户端基线以来改变的资源
  → 保留等待期间的新输入，合并独立页面更新
```

日常保存读取数据库中的资源版本、页面身份、路径、状态和字节数，不把无关页面正文读回 Worker 再做全量解析。页面删除保留版本标记，避免删除后重用 ID 绕过并发保护。

容量限制为单资源 1,800,000 字节、工作区 8,000,000 字节、2,000 个活动页面、每页 300 模块。图片不进入正文数据库行。D1 官方的单值/行上限是 2,000,000 字节，每条 SQL 文本上限是 100 KB；初始化导入对长文分段，并支持同一导入文件中断后重试。[D1 平台限制](https://developers.cloudflare.com/d1/platform/limits/)

数据库升级为一次性迁移，旧表迁移后删除；没有保留两套运行时或旧版回退代码。资源限制同时在应用和数据库层实施，没有通过单纯提高整站行上限来规避平台约束。
