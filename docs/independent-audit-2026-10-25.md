# 独立审计与修复 · 2026-10-25

## 范围与结论

本轮由一个不继承前轮讨论的新 agent 先读源码，再设计新场景，之后才参考历史报告。独立审查者不修改业务代码；主 agent 核实并修复，独立审查者使用原失败场景复测。所有写入测试都使用隔离的 4173 / 8788 服务和 `.artifacts/e2e-state`，不重置日常预览数据库，不连接生产数据库，不提交、推送或部署。

审查认为当前架构适合这个个人站规模：TypeScript 统一类型；Zod 定义内容边界；Astro 负责公开页面生成；React / Tiptap 负责后台编辑；共享展示组件保持预览与公开站一致；Access、Worker、D1、私有 R2 分别承担认证、服务、版本和资产存储。评价依据是模块责任与实际行为，不是依赖版本号或框架数量。独立 agent 对本轮修复另做只读复核，未发现新增的明确漏洞或阻塞问题。

本轮确认的 11 项问题已修复并完成对应回归，未留下本轮已复现而未处理的代码缺陷。当前可以进入**受控的真实后端联调**。这不等于已经完成生产验收；实际账户、Access 策略、GitHub 发布、云端恢复、真实移动设备及最终 CDN 性能仍需验证。最终复测结果见下文。

| IMG-01 | P2   | 构建在公开上传目录原地重编码，再次构建又使用上次压缩结果，JPEG 会重复损耗                  | 原图放在私有构建暂存目录，公开目录只作为输出；构建先验证原图哈希，再去元数据、转正和生成尺寸；派生文件按实际输出字节哈希命名。重复构建测试验证原图不变、输出一致、元数据移除及未引用文件不发布 |

对应模块：`HistoryPanel` 负责恢复生命周期；`useDraft` 负责统一保存调度；`Dialog` 负责焦点生命周期；`image-policy` 负责 CSP；`image-preview` / `editorial-image` 分离轻量缩略图与延迟加载的富文本扩展；`release-artifacts` 负责产物冻结；`repository` 负责保存事务；`scripts/assets/uploads` 负责不可变原图构建。没有引入另一套 CMS、通用服务层或旧运行时兼容分支。

事务设计按 [Cloudflare D1 batch 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch) 的顺序执行和整体回滚语义实现。本地 SQLite 故障注入验证实际 SQL，仍不能替代远端 D1 验收。

## 进入线上测试的条件与边界

1. 恢复 Cloudflare 登录，确认账户，创建/绑定实际 D1、私有 R2、Images；填入生产参数并通过 `pnpm backend:check`。
2. 创建管理员 `/admin/` Access 应用和申请卡独立 Access 应用，验证匿名、错误 audience、错误邮箱与构建身份都被拒绝；只管理 `www.lzzhu.net` 的既定路径。
3. 在真实账户验证草稿保存、上传、预览、服务令牌、GitHub dispatch、发布标记核对、回滚，以及 D1 / R2 恢复。保留旧线上部署，完成验收后再切换。
4. 原申请卡服务上轮仍返回 HTTP 500，尚未取得余额和历史。恢复读取或取得可靠备份并核验后才切换这部分；新库初始 0 不是迁移结果。本轮没有重新请求旧服务。
5. 实测 iPhone / Android / Windows 的键盘、VoiceOver / TalkBack / NVDA、缩放、主题和朗读；重新测最终域名性能。

明确的扩容边界：整站文档目前上限 1.8 MB，撤销最多保留 50 份完整快照，适合现有内容规模；持续增长前应改按页面持久化及更窄的历史记录。素材库当前最多列出最新 500 项，分页和保留策略属于后续容量工作；不可猜测删除旧素材，因为历史版本与回滚仍可能引用它们。这些不是当前内容的已复现故障，也没有被表述为无限扩展能力。

图片策略的明确边界：外部图应使用最终 HTTPS 直链；跨域重定向不会自动扩展来源权限。页面预览目前汇总已保存内容的图片域名，来源很多时应进一步按当前页面裁剪。失败或竞争失败的产物上传可能留下未引用的私有对象，需要后续有证据的保留/清理策略，不能直接删掉历史资源。
