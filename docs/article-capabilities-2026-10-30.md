# 博客、文章配置与数学公式：功能清单

2026-10-30。本文对应本轮第 4 项调研；表内新增能力尚未实现。现有公开页面的版式不因这份方案改变。

## 为什么作者出现两次

现在的网站由 Astro 生成公开页面，Admin 使用 React/Tiptap，内容由自己的结构化模型管理，没有继续运行 Hexo。

不过文章外观保留了旧 Chic 主题的结构：顶部作者与日期，底部作者、永久链接与许可，再接标签和上一篇/下一篇。Chic 原本可以分别关闭顶部作者与底部作者；目前的新站 `site-shell.tsx` 将这两处直接渲染出来，没有迁移相应开关。它还保留了空的 `Tag(s):` 标题，但当前内容模型没有文章标签字段。因此，重复作者与空标签确实需要整理，不能靠修改 Hexo 配置解决。[Chic 文章模板](https://github.com/Siricee/hexo-theme-Chic/blob/master/layout/_page/post.ejs)、[主题配置](https://github.com/Siricee/hexo-theme-Chic/blob/master/_config.yml)

建议默认只在文章顶部显示作者和日期；底部按需显示版权与许可，没有标签就不显示标签行。是否展示永久链接应是独立选项。版权归属、使用许可和文章作者是三个不同字段，不应都挤在一个 Copyright 输入框里。

## 可以配置哪些功能

“已有”指当前仓库中可以使用；“新增”指需要实现，不代表已经上线。

| 功能 | 当前情况 | 建议的 Admin 配置与默认行为 |
| --- | --- | --- |
| 标题、地址、语言、草稿/发布 | 已有 | 保留在文章基本信息；修改已发布地址时提示旧链接影响 |
| 作者 | 全站一个作者，公开页面重复显示 | 网站设置保存默认作者；文章可覆盖；顶部默认显示一次 |
| 发布时间 | 已有日期与可选时间 | 明确时区；支持显示日期、日期与时间、隐藏；无日期文章单独归类 |
| 更新时间 | 无独立编辑字段 | 新增；“保存时间”与“对外展示的更新时间”分开 |
| 摘要与封面 | 有 SEO description 和正文图片，没有独立文章摘要/封面 | 新增文章摘要与封面；SEO 描述可继承摘要，列表无需从正文猜图 |
| 标签 | 尚无模型或编辑能力 | 新增可复用标签目录；输入时选择已有标签或新建；空值不占位置 |
| 分类 | 尚无 | 首期可选单层分类；暂不引入复杂树状分类，避免与标签重复 |
| 版权归属 | 当前只有自由文本 Copyright statement | 改为 Rights holder、Copyright year；默认继承站点设置，可按文章覆盖 |
| 使用许可 | 已有名称与 URL 输入 | 独立 License 选择器：保持现有许可、保留所有权利、自定义；不替作者自动改为开放许可 |
| 文章展示开关 | 缺少独立开关 | Article appearance：作者、日期、更新时间、标签、版权、永久链接、上下篇导航 |
| 目录 | 当前没有自动目录 | 根据正文标题生成，文章可开关；标题锚点稳定，键盘可操作 |
| 文章列表模块 | 已有，能放在不同页面，支持固定年月范围 | 增加标签/分类范围、排序、每页数量、摘要/封面显示选项 |
| 公开列表搜索与筛选 | 当前只有静态分年列表 | 在列表上方提供搜索、年份、标签、排序和清除筛选；状态写入 URL，刷新与后退可恢复 |
| Admin 文章检索 | 已有标题/路径搜索、年份、状态、排序与分页 | 延续单一列表，不恢复 Archive views 标签页；新增标签/分类筛选 |
| 全文搜索 | 尚无 | 发布时生成仅含公开文章的轻量索引；使用搜索时才加载。规模增长后再换服务端查询 |
| 富文本与 Markdown | 已有双模式 | 增加元数据面板，正文编辑器继续专注正文；格式往返不能丢失链接、图片或公式 |
| 数学公式 | 当前没有数学节点或渲染器 | 新增行内、独立公式；富文本可插入/编辑，Markdown 支持约定的 LaTeX 分隔符 |
| 代码块 | 有代码块结构，未提供完整语法高亮设置 | 可补语言选择、构建时高亮与复制按钮；不全站加载高亮库 |
| RSS / 分享 / SEO | Medium 官方 RSS 接入、基础 SEO 与 OG 已有；本站文章 RSS 未生成 | 本站 RSS 单独生成；OG 可配置文章封面；仅公开可索引内容进入索引与订阅 |
| 评论 / 阅读统计 / 定时发布 | 尚无完整能力 | 暂不默认加入；它们涉及新后端、隐私与定时执行，不是主题开关即可完成 |

Hexo 的文章 front-matter 原本提供 tags、categories、date、updated、excerpt、lang、published 等字段；标签为平级集合，分类可以有层级。我们可以采用这些成熟概念，但 Admin 应提供正常的表单，无需用户编写 YAML。[Hexo front-matter 文档](https://hexo.io/docs/front-matter)

## Admin 怎样组织

网站设置中的 **Articles** 管默认作者、默认许可和默认展示方式；文章编辑页分 **Content**、**Details**、**Search & sharing**。Details 中依次放作者、发布日期、标签/分类、版权与许可。继承项显示 “Use site default”，覆盖后显示实际值，用户能看懂改动范围。

各页面里的 **Article list** 只决定展示哪些文章、顺序和版式。文章本身仍只有一份，放到 Blog、Past 或其他页面不复制内容。Past 的导航隐藏独立于文章公开状态；隐藏导航不等于访问权限保护。

公开列表的首期组合建议为“搜索 + 年份 + 标签 + 最新/最早”，无需同时铺开所有高级选项。筛选后保留结果数和清除入口；空结果应可撤销筛选，不能成为死路。

## 数学公式如何接入

Chic 确实有 MathJax 开关，支持全站加载或文章按需加载。它的按需方式依靠 Hexo front-matter；新站不会读取这个开关。[Chic MathJax 配置](https://github.com/Siricee/hexo-theme-Chic/blob/master/_config.yml)

有两条可行路线：

| 路线 | 适合情况 | 需要承担的工作 |
| --- | --- | --- |
| Tiptap 官方数学扩展 + KaTeX | 常见教学和研究公式，优先减少自定义编辑器工作 | 官方扩展已提供行内/独立节点；仍需我们完善内容验证、Markdown 往返、公开渲染、键盘交互和无障碍验收 |
| 自定义 Tiptap 数学节点 + MathJax 4 | 更广的 TeX 需求或需要 MathJax 的公式探索、语音等能力 | 编辑器预览适配器、构建渲染器及错误处理由我们实现；不能假定装入官方 Tiptap 数学扩展就会使用 MathJax |

Tiptap 官方扩展明确使用 KaTeX。若本轮目标只是“能写常见数学公式”，建议优先第一条；若要明确采用 MathJax，则选第二条，并让后台和公开站使用同一套引擎、宏定义及输出规则，避免双引擎差异。[Tiptap 数学扩展](https://tiptap.dev/docs/editor/extensions/nodes/mathematics)

共同的数据层保存 LaTeX 原文和行内/块级类型，不存放任意 HTML。公开站在发布时排版；后台只在打开公式编辑时加载渲染器。MathJax 支持 Node 环境中的组件或直接模块调用，可用于构建阶段。[MathJax Node 文档](https://docs.mathjax.org/en/latest/server/start.html)

数学支持属于共享富文本能力，因此文章、研究描述和普通文本模块都能使用，不做成只在 Blog 生效的特殊分支。Markdown 采用 `$…$`、`$$…$$` 时，要明确转义货币符号、忽略代码块，并验证富文本与 Markdown 往返。

安全边界包括公式长度和渲染耗时上限、允许的宏与 URL 协议、出错位置提示、非法输入不能拖垮保存/发布。MathJax 提供 safe 组件处理公式中的危险链接等内容，但它不替代应用的数据验证。[MathJax safe 组件](https://docs.mathjax.org/en/latest/web/components/misc.html)

视觉公式不能只导出不可读的图片；应保留可访问的数学语义，并在 VoiceOver/NVDA 上实际验证。MathJax 4 的组合组件默认启用语音与公式探索扩展；自行预渲染时仍需明确哪些能力随页面交付，不能把默认组合包的能力自动算在我们的静态输出上。[MathJax 无障碍说明](https://docs.mathjax.org/en/latest/basic/accessibility.html)

## 实施顺序和验收

1. 先建立文章元数据、站点默认值和覆盖规则，拆分 ArticleMeta、ArticleRights、ArticleTags、ArticleNavigation。迁移保留原文和许可，不推断缺失作者、年份或标签。
2. 接入标签与公开列表筛选，复用 Admin 列表查询规则。验证中文、大小写、组合筛选、无日期文章、分页、后退与无结果状态；索引不能含草稿。
3. 接入选定的数学引擎。验收分数、矩阵、多行公式、中文相邻文本、长公式手机横向处理、Markdown 三次往返、无障碍朗读和非法输入。
4. 用千篇文章、长文及大量公式验证发布耗时、搜索响应与后台编辑内存；保留现有资源级保存和并发冲突保护。

本轮只形成上述调研与配置方案，没有悄悄启用新博客格式、标签或公式，也没有改变已有文章的版权条款。
